# 阅读器维护说明

角色的所有阶段集中在一份文件里。共通文字写一次，章节只选择角色及其阶段。百科使用相同的规则。修改来源后运行 `python reader/build.py`，生成可以直接静态托管的网页。

## 平时在哪里修改

以下位置以本目录 `reader/` 为起点。

| 修改内容 | 文件位置 |
| --- | --- |
| 一个角色的全部简介、各阶段差异 | `source/characters/角色名.json` |
| 一项百科的全部内容、各阶段差异 | `source/terms/百科名.json` |
| 每章的卡片、顺序、分页、角色阶段、解锁状态 | `source/pages/页面名.json` |
| 章节标题、摘要、正文文件、目录顺序 | `source/series/*.json` |
| 工具栏共通设置、章节配色差异 | `source/toolbar/defaults.json` 和 `profile-*.json` |
| 页面、目录、按钮、卡片的共通结构 | `templates/` |
| 目录、加载正文、角色／百科分页 | `runtime.js` |
| 阶段规则的校验与生成 | `details.py` |

小说正文继续编辑项目根目录原有 TXT 文件。字号、昼夜、隐藏按钮、跨系列快捷入口在根目录 `multiuse_scripts.js`；资料页切换在 `scripts_resource.js`。

## 角色文档：共通内容只写一次

例如 `source/characters/向濑白夜.json` 已包含两个阶段：早期简介、补充游戏习惯后的简介。共通部分是一条字符串，新增情报用 `from: 2` 表示从阶段 2 开始出现。

下面是缩短后的格式示例，文字仅用于说明规则：

```json
{
  "stages": {
    "1": "初次登场",
    "2": "获知新情报",
    "3": "更换武器",
    "4": "番外视角"
  },
  "content": [
    "所有非零阶段共用的简介。",
    {"from": 2, "html": "<br>阶段 2 及以后显示的新情报。"},
    {"until": 2, "html": "<br>阶段 1、2 使用的旧武器。"},
    {"from": 3, "html": "<br>阶段 3 及以后使用的新武器。"},
    {"only": [2, 4], "html": "<br>仅阶段 2、4 显示的描述。"}
  ]
}
```

`content` 按书写顺序拼接，不会自动加换行；沿用 `<br>`、`<span>` 等 HTML。字符串中的英文双引号要写成 `\"`。JSON 不支持行末逗号或 `//` 注释，需要说明时可以在文档或规则对象内加 `"note": "说明文字"`，不会显示到网页上。

| 写法 | 显示范围 |
| --- | --- |
| 普通字符串 | 所有已声明的非零阶段 |
| `{"from": 2, "html": "..."}` | 从 2 开始，包括 2 |
| `{"until": 3, "html": "..."}` | 到 3 为止，包括 3 |
| `{"from": 2, "until": 4, "html": "..."}` | 2、3、4 |
| `{"only": [1, 4], "html": "..."}` | 仅 1、4 |
| `{"from": 2, "except": [3], "html": "..."}` | 从 2 开始持续显示，仅排除旧阶段 3；新增阶段也会继承 |

角色信息默认延续：第 16 章（`mousou_chapter18.html`）仍然有效的描述使用没有 `until` 上限的 `from`；只有明确已经消失、被替换或属于旧视角的描述才使用 `until`／`only`。尚未在主线出现的角色，沿用其最后一次正常登场时的资料。共通字符串本身也会自动延续。

个别番外、资料页、未解锁预览的阶段编号比当前主线阶段大。对这些历史特例使用 `except` 排除具体阶段，不影响以后新增阶段的继承。例如茶屋和伊从阶段 2 开始的描述使用 `from: 2, except: [3]`：旧预览阶段 3 不显示，新增阶段 4、5 等都会显示。`except` 只能搭配范围规则，不能和 `only` 同用；其中的编号必须是已声明且处于范围内的阶段。

互斥描述使用不重叠的范围、明确例外或 `only`。例如绫栾的赤手空拳状态默认延续，重藤弓等旧视角被限制在对应阶段，人物的共通简介仍只有一份。规则是独立片段，不会自动互相覆盖；若两个条件都成立，两段都会显示。

阶段数字只属于这个角色／词条，并非全站章节编号，也不代表战斗等级。主线和番外可以选择不同阶段。现有 `stages` 的说明记录了该份资料首次使用的页面，方便辨认；可以改成自己更熟悉的阶段名。阶段 0 固定为空简介，不需要在 `stages` 中声明。

以后新增阶段时，编号取这个角色已有最大编号加 1，先在 `stages` 中加入数字和说明，再配置新增／替换片段。共通字符串和没有 `until` 上限的 `from` 会延续到新阶段；`only` 不会自动延续，`except` 只排除列出的旧阶段。新增正常主线阶段不需要逐条补充旧描述的编号。为番外新增独立视角时，再明确列出该视角需要排除或替换的内容。

## 每章只选择资料与阶段

`source/pages/mousou_chapter18.json` 中白夜的卡片类似：

```json
{
  "label": "向濑白夜",
  "id": "character1",
  "class": "character-tab",
  "enabled": true,
  "character": "向濑白夜",
  "stage": 2
}
```

`character` 对应角色文件名，`stage` 选择资料阶段；百科改用 `"term": "词条名"`。`label` 是卡片标题，`id`、`class` 保留现有界面标识，通常不需要动。`enabled` 控制卡片是否可用，与阶段选择独立。

修改共通介绍：只编辑角色文档里的共通字符串，生成后所有引用该角色的相应章节都会更新。新增剧情情报：在同一文档里加条件片段，再调整需要获知情报的章节的 `stage`。不用复制整个简介，也不用修改其他角色的文件。

各章的 `panels` 仍明确控制卡片分组、顺序和分页。角色、百科按各自的实际页数循环；切换种类回到第一页，关闭时显示 Pg.0。

## 生成与检查

在项目根目录运行：

```powershell
python reader/build.py
python reader/build.py --check
python -m unittest discover -s reader/tests -v
```

生成器先验证全部资料和章节，再写入 HTML 与六套章节脚本，自动重算正文字数。引用不存在的角色或阶段、规则字段拼错、无效范围等会报出文件位置；不会悄悄使用最新阶段。生成只写入该章所选阶段的资料，不会把这个角色其他阶段的全文一起塞进页面。

Python 只在维护时使用，无需安装额外 Python 包，读者不需要 Python。页面保留原网址，线上不需要逐个请求角色文档；目录也不需要请求所有正文来统计字数。

根目录各章 HTML，以及 `scripts.js`、`scripts_side2.js`、`scripts_sideg.js`、`scripts_sideg2.js`、`scripts_sideg3.js`、`jiken_scripts.js` 是生成产物。请提交／上传更新后的来源和生成产物；直接改生成文件会在下次生成时被覆盖。正文、样式和手写公共脚本不属于生成产物。

## 新增章节

1. 新建正文 TXT。
2. 在对应 `source/series/*.json` 的 `chapters` 中添加网址 `url`、正文 `filePath`、标题、短标题、摘要和 `kind: "story"`。目录按照该数组顺序排列；正文与高亮按网址对应。
3. 复制相近的 `source/pages/*.json`，修改 `url`、页面标题，并选择每张卡片的角色／百科、阶段、解锁状态。
4. 新人物只需在 `source/characters/` 增加一份同名 JSON；新百科放进 `source/terms/`。
5. 如需“◇”跨系列快捷菜单的新入口，更新 `multiuse_scripts.js` 中对应配置。
6. 运行生成与检查。

`mousou_chapter6.html` 保持 `kind: "resource"`，普通主线目录隐藏它，特殊入口和工具照旧。对话、法典继续使用 `chapter999.txt`、`chapter998.txt`，计算器使用原 `calculator.js`。

## 回归测试与迁移说明

自动检查包括：共通修改同步到各阶段、早期章节不混入后期情报、范围与指定阶段的选择、主线信息跨过历史例外后继续延续、旧描述不在新阶段复活、无效配置报错、资料页标记、生成结果是否同步。

本次迁移逐项比对了原有 166 份资料版本、39 页的 1,598 张卡片。仅合并了 HTML 本来就会折叠的普通空白，保留文字、标签、全角空格、换行标签和解锁状态。全站浏览器对比与功能回归脚本位于 `tests/`：

```powershell
node reader/tests/browser-features.cjs
node reader/tests/browser-compatibility.cjs "改动前网站副本目录"
```

浏览器测试需要 Playwright，默认使用 Edge。可设置 `READER_PLAYWRIGHT_MODULE` 和 `READER_BROWSER_PATH` 指定本机路径。测试拦截外部评论和媒体请求，不测试外部评论服务。今后主动修改内容后，对比旧副本出现差异属于正常现象。

本次只删除已被单份阶段文档替代的 `source/details/` 内 166 份旧版本文件及其空目录。根目录仍在使用的网页和脚本保留。本来就未使用的文件，以及 `episode`、`katashigure`、`NoLongerInUse`、非商业音乐游戏运营模拟器和 n-cryos 系列均不纳入清理。
